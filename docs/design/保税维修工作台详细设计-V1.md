## 2. 数据库设计

### 2.1 镜像表（推送海关）
严格按《企业客户端数据采集传输规范 v1.4》§3.1.2～§3.5.2 建表脚本执行：
`epd101_data`、`pto2_data`、`rrd2_data`、`mso2_data`、`sdo2_data`。
- 与业务表同库；系统只 INSERT / 只读回执字段（`uuid/result_status/msg/result_time/over_time`），禁止 UPDATE 业务字段。
- 变更/作废 = 新增行（execute_type=2/3），不做行内修改。

## 3. 申报引擎设计

### 3.1 申报流程（PTO2 为例，其余同构）
1. 前端调 `POST /declare/submit?bizType=PTO2&bizId=x`；
2. 服务端校验：doc_status=03（审核通过）、物料备案有效、数量余额充足；
3. 事务内：按单据头/明细生成镜像表行（字段映射见 §4）→ INSERT 镜像表 → INSERT br_declare_log（sync_flag=0）→ 更新单据 doc_status=04、last_uuid、execute_type 保留；
4. 失败整体回滚，单据停留 03。

### 3.2 回执同步（三种通道）
| 通道 | 实现 |
|---|---|
| 轮询兜底 | 定时任务（默认 60s，可配）：扫 br_declare_log sync_flag=0 的 mirror_row_id，读镜像表回执字段回写 log 与业务单据状态（Y/1→05，N/3→06 并带 msg） |
| 补偿查询 | 20/21（已采集/申报中）状态超 30 分钟无回执 → 自动触发主动查询，当天每单上限 10 次；写入镜像表超 24h 无回执置 customs_status=90（采集超时） |
| 公服回调 | 暴露 `POST /api/callback/customs`（免鉴权白名单+签名校验），按 preNo+syncBusiType 匹配 br_declare_log 回写，幂等处理 |
| 主动查询 | 调公服 `https://psp.singlewindow.hn.cn/gongfu/api/secure/router`，x-app-key + RSA 加签（公钥配置于 sys_config），用于批量核对与人工刷新 |

### 3.3 退单重报
退单（N/3）→ 单据转 06 可编辑 → 改单后"申报"时 execute_type=2（变更），作废按钮生成 execute_type=3 行。

## 4. 字段映射（业务行 → 镜像表行）
- 公共头：enterpCd=参数 br.enterpCd；syncBusiType=业务类型；syncTime=now；executeType=单据 execute_type。
- EPD101：br_material → epd101_data（int_product_name 拼接六类标记后缀，如"动力电池模组（待修复）"）。
- PTO2：br_inbound + br_inbound_item → pto2_data（一行/明细）。
- RRD2：br_issue + br_issue_item → rrd2_data；material_desc 取 br_material.material_name + 标记。
- MSO2：br_receive + br_receive_item → mso2_data；服务费行 material_cd/desc=被维修商品编码+"维修服务费"，material_num=0.1，price=服务费÷0.1。
- SDO2：br_outbound + br_outbound_item → sdo2_data。
- 映射模板以样例集 01～07 的 JSON 为回归基准（单元测试逐例断言）。

## 9. 风险与约定
1. 镜像表 DDL 必须与规范脚本逐字一致（字段类型 decimal(19,6)/(28,6) 等差异敏感），上线前用客户端做一次试采集。
2. 时区/日期格式统一 yyyy-MM-dd HH:mm:ss；数量不出现科学计数法。
3. 服务费单价按 0.1 换算存在除不尽风险：单价保留 6 位小数，四舍五入规则与客户端校验一致（按样例集演示值核对）。
4. 回调接口需向公服报备地址；上线前三种回执通道均需在测试环境（test-psp）联调。
5. 海关接口/客户端版本变更（承草稿 §12.2）：预留申报引擎适配层，镜像表映射集中管理，变更时只改映射不改业务。
6. 客户端部署问题：提供部署配置文档与采集状态监控告警（customs_status=90 首页横幅提示）。

**海关状态 customs_status**（统一 2 位编码，详见 PRD §4.2）：与业务 doc_status 并存存储，前端以颜色标签展示，点击弹出回执详情（br_declare_log 全量 JSON）。
