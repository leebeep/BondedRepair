## 1. 项目背景与目标

### 1.1 背景
保税维修企业须按公告 203 号对**待维修货物、已维修货物、无法维修货物、维修用料件、旧件坏件、边角料**六类货物专门管理，并通过"加工增值企业客户端"向海关报送 ERP 四类单证（入库/出库/工单发料/工单收料）与料件成品备案数据。

### 1.2 目标
基于若依（RuoYi）框架搭建保税维修工作台，实现：
1. 关务人员在系统内**完成全链路录单**：物料备案 → 入库 → 工单发料 → 工单收料 → 出库；
2. 采用**数据库镜像方式**对接海关：业务单据审核通过后，按规范 v1.4 的镜像表结构写入 `epd101_data / pto2_data / rrd2_data / mso2_data / sdo2_data` 五张表，由企业客户端自动采集、加密加签后传输海关；
3. 系统回读镜像表回执字段（`uuid / result_status / msg / result_time`），实现**申报状态跟踪与退单重报**；
4. 提供**六类货物库存台账与据实核销对账**，确保流量账闭环（对账公式见 §7）。

### 1.3 非目标（本期不做）
- 不做报关单（单一窗口）申报，仅做保税维修 ERP 数据报送；
- 不做财务/应收应付；
- 不做客户端本身的安装与配置（由实施人员在客户端侧完成）。

### 1.4 术语定义
| 术语 | 定义 |
|---|---|
| 保税维修 | 在海关特殊监管区域内，对来自境外的损坏货物进行维修后复运出境的业务 |
| 料件成品备案 | 企业向海关申报物料/产品信息（EPD101），获得预录入编号 |
| 加工增值企业客户端 | 海关提供的企业端数据采集软件，负责数据校验、加密加签传输 |
| 预录入编号 | 海关系统返回的业务单据唯一标识（enterpUuid / uuid） |
| 单一窗口 / 公服平台 | 海南国际贸易单一窗口平台（psp.singlewindow.hn.cn） |
| 六类标记 | 待修复/已修复/无法修复/维修用保税料件/旧件坏件/边角料品名后缀 |

## 4. 核心业务流程

### 4.1 总体流程
```
物料备案(EPD101) ──审核通过──► 海关备案
        │
维修工单立项
        │
① 待维修货物/维修用料 入库(PTO2, busiType=04/05)
② 工单发料(RRD2)：待维修货物+用料 投入工单
③ 工单收料(MSO2)：已修复(5)/残次品(a)/未使用料件(1)/维修用料件(6)/坏损件(7)/边角料(9)/维修服务费(8)
④ 出库(SDO2, busiType=04-复运出境)：已修复/无法修复/未投入退运/旧件/边角料/余料
        │
每步"提交申报" ──► 写镜像表 ──► 客户端采集 ──► 海关 ──► 回执写回 ──► 状态更新
```

### 4.2 单据状态机（统一海关状态 customs_status，2 位编码）

> 适配说明：本系统采用数据库镜像方式（无系统直调客户端 API 环节），草稿中的"推送中(10)/推送失败(90)"语义调整为"待采集/采集超时"。

| 状态代码 | 状态名称 | 说明 | 颜色 |
|---|---|---|---|
| 00 | 未申报 | 单据已保存/审核通过，尚未写入镜像表 | 灰色 |
| 10 | 待采集 | 已写镜像表，客户端尚未采集 | 蓝色 |
| 20 | 已采集 | 客户端已采集传输，等待海关回执 | 青色 |
| 90 | 采集超时 | 写入镜像表后长时间（默认 24h，可配）无回执 | 红色 |
| 21 | 申报中 | 收到回执处理中状态 | 橙色 |
| 2Y | 入库成功 | 回执 manageResult=Y | 绿色 |
| 2N | 入库失败 | 回执 manageResult=N | 红色 |
| 22 | 通过 | 回执 manageResult=1 | 绿色 |
| 23 | 转人工 | 回执 manageResult=2 | 黄色 |
| 24 | 退单 | 回执 manageResult=3 | 红色 |
| 29 | 已作废 | executeType=3 申报完成 | 灰色 |

**业务单据状态与海关状态并存**：`doc_status`（草稿/待审核/审核通过/已申报/申报通过/退单/已作废）控制单据操作权限，`customs_status` 展示申报进度。
- 退单（2N/24）单据修改后以 `execute_type=2`（变更）重报；作废以 `3`。
- 已申报通过（2Y/22）的单据**禁止修改/删除**，只能红冲或异常调整（relaCustomsFormType=05）。
- 列表中点击海关状态弹出**回执详情弹窗**：序号、操作（备案/变更/作废）、回执完整 JSON、操作时间。

## 5. 功能模块

### 5.1 基础档案
| 模块 | 说明 |
|---|---|
| 企业信息 | 企业海关编号 enterpCd、企业名称、主管关区（6404 洋浦/6411 海口），全局参数 |
| 物料备案（EPD101） | 物料编号+版本+计量单位联合唯一；gType(I/E/S)、isBonded、HS 编码、品名标记（六类后缀，见 §6.1）、征免方式等；支持备案/变更/作废三种 executeType |
| 海关字典 | 计量单位、币制、国别地区、监管方式、征免方式（预置规范附录与通关参数，可维护） |
| 委托方档案 | 境外委托企业名称（relaEntNm）、国别，供入库/出库单引用 |

### 5.2 维修工单（系统核心，镜像表无此表）
| 字段组 | 内容 |
|---|---|
| 工单头 | 工单号 workNo、委托方、申报批次号（如 B202611-001）、管理粒度（批次/SN 单件）、核销周期、状态 |
| 工单明细 | 投入的待维修货物（来源入库单）、预计用料、维修服务费金额 |
| 关联 | 发料单（可多张）、收料单（可多张，含各 returnType） |

工单是 RRD2/MSO2 的 workNo 来源；管理粒度统一为**批次**，SN 单件台账本期不做（结构预留扩展）。

### 5.3 入库管理（PTO2）
- 业务类型：04-待维修货物、05-维修用料（本期主用）；01/02/03/99 预留。
- 录入字段按规范 §2.2.2 全量：takeOrderCd、materialCd/Desc/Version、specificationsModels、storageCnt、price、currency、calcUnit、inOutTime、isBonded、relaCustomsFormType/Num、brandType、tradeModeCd、unit1Num/unit2Num、启抵国/原产国等。
- 校验：物料必须已备案且保税料件必填 HS；busiType=99 必填 busiDesc。
- 一单可多物料行（镜像表按行写多条 pto2_data）。

### 5.4 工单发料（RRD2）
- 从入库单（goodsSourceType=g）或收料单（i）发料；workNo 关联工单。
- 待维修货物**必须随工单发料**（样例集约定 6），系统强制：工单开工前生成发料单，品名带"（待修复）"标记的库存方可发料。

### 5.5 工单收料（MSO2）
- 收料类型 returnType：1-未使用料件、5-已维修货物、6-维修用料件、7-坏损零部件、8-维修服务费、9-边角料、a-残次品（本期主用；2/3/4 预留）。
- **维修服务费**（returnType=8）：物料编码/名称 = 被维修商品编码及名称 +"维修服务费"，数量固定 0.1，单价 = 服务费总额 ÷ 0.1；系统按工单服务费自动生成该行。
- 坏损件/边角料行物料须关联已备案物料（gType=I, isBonded=1），品名自动加"（维修替换下的旧件或坏件）/（维修产生的边角料）"标记。

### 5.6 出库管理（SDO2）
- 业务类型：04-复运出境（主用）、05-复运回境内区外（维修费照章征税场景）、03-销毁（预留）。
- 来源：已修复/残次品/坏损件/边角料/未使用料件库存（goodsSourceType=i，goodsSourceNo=收料单号）、余料（来源入库单）。
- 已维修货物复运回境内区外时，系统强制同单出库 returnType=8 形成的"维修服务费"库存行（数量 0.1）。

### 5.7 申报管理（推送海关）
| 功能 | 说明 |
|---|---|
| 提交申报 | 单据审核通过后一键"申报"，事务内写镜像表（executeType=1 首报 / 2 变更 / 3 作废），回填 uuid |
| 申报看板 | 按业务类型列出镜像表记录：海关状态（customs_status，含颜色标签）、回执消息 msg、回执时间 result_time、重试次数 over_time；筛选维度：业务类型/状态/时间范围/单据编号 |
| 回执同步 | 定时任务轮询镜像表回执字段 → 更新业务单据状态；退单标记原因并允许改单重报 |
| 公服回调 | 暴露回调接口接收海关异步回执（免鉴权白名单 + 签名校验），幂等处理 |
| 主动查询 | 调公服查询接口（x-app-key + RSA 加签，executeType=4），手动"查询回执"按钮（仅 20/21 状态显示）与批量查询 |
| 数据预检 | 提交前按规范必填/枚举/长度校验（服务端复刻客户端校验规则），减少客户端校验失败 |

#### 5.7.1 异常处理（承草稿 6.7.2，适配镜像方式）
| 异常类型 | 海关状态 | 处理方向 |
|---|---|---|
| 采集超时 | 90 | 检查客户端运行/采集配置后，可通过主动查询刷新；仍无回执则联系实施排查 |
| 入库失败 | 2N | 查看回执错误信息 → 编辑修正 → 变更重报（execute_type=2） |
| 退单 | 24 | 同上；无法修正可作废后重开单据 |
| 转人工 | 23 | 查看原因，备齐证明材料，联系海关跟进，等待最终结果 |

**批量操作**：批量查询回执（20/21 状态）、批量作废（00 状态）、导出异常清单（Excel）。
**自动补偿查询**：定时扫描 20/21 状态且距最后更新超 30 分钟的单据，自动触发主动查询，当天每单最多 10 次。
**首页告警区**：展示今日异常单据数量（采集超时/入库失败/退单），一键跳转异常列表。
**申报可靠性指标**（承草稿 §11.4）：写入镜像表成功率 100%（事务保证）、状态最终一致、异常单据持久化不丢失、补偿扫描覆盖 100%。

## 6. 关键业务规则

### 6.1 六类货物名称标记（备案与单据联动）
| 类别 | 品名标记 | EPD101 备案 | 入库 busiType | 收料 returnType | 出库 busiType |
|---|---|---|---|---|---|
| 待维修货物 | 品名（待修复） | 料件 I | 04 | — | 04（未投入退运） |
| 已维修货物 | 品名（已修复） | 成品 E | — | 5 | 04 |
| 无法维修货物 | 品名（无法修复） | 成品 E | — | a | 04 |
| 维修用料件 | 品名（维修用保税料件） | 料件 I | 05 | 1/6 | 04（余料） |
| 旧件坏件 | 品名（维修替换下的旧件或坏件） | 料件 I | — | 7 | 04 |
| 边角料 | 品名（维修产生的边角料） | 料件 I | — | 9 | 04 |

系统根据单据类型/业务类型自动选择对应标记物料，禁止人工改写标记。

### 6.2 强制校验
1. 单据引用的物料必须存在有效备案（isBonded=1 必有 HS 编码）。
2. 发料数量 ≤ 该入库单/收料单可发余额。
3. 收料数量 ≤ 工单实际投入（returnType=5+a 之和 = 实际投入数；允许分批收齐）。
4. 出库数量 ≤ 对应收料/入库单库存余额。
5. 工单结案前置条件：投入=已修复+无法修复收齐，且六类账存=0（或余料结转）。

## 7. 库存对账公式（报表口径）
- 待修复账存 = 入库(04) − 发料 + 未使用收料(1) − 未投入退运 = 0
- 实际投入 = 发料 − 未使用收料 = 已修复(5) + 无法修复(a)
- 料件账存 = 入库(05) − 发料 + 余料收料(6) − 余料复运 = 结转下期
- 已修复/无法修复/旧件/边角料账存 = 收料 − 出库 = 0

## 8. 数据库设计（要点）

### 8.1 镜像表（推送海关，按规范 v1.4 建表脚本，不加业务字段）
`epd101_data`、`pto2_data`、`rrd2_data`、`mso2_data`、`sdo2_data`
- 回执字段：`uuid`、`result_status`、`msg`、`result_time`、`over_time` 由客户端写入，系统只读。
- 写入即"申报"，字段命名/类型严格按 §3 建表脚本（decimal(19,6)/(28,6)、varchar 长度等）。

### 8.2 业务表（新增，前缀 `br_`）
| 表 | 说明 |
|---|---|
| br_material | 物料主数据（与镜像备案数据 1:N 版本映射，含六类标记类型） |
| br_work_order / br_work_order_item / br_work_order_sn | 维修工单头/明细/SN 台账 |
| br_inbound / br_inbound_item | 入库单（生成 pto2_data） |
| br_issue / br_issue_item | 发料单（生成 rrd2_data） |
| br_receive / br_receive_item | 收料单（生成 mso2_data） |
| br_outbound / br_outbound_item | 出库单（生成 sdo2_data） |
| br_stock_ledger | 六类库存流水（收/发/出各环节登记，供对账） |
| br_declare_log | 申报日志（单据↔镜像表 id↔uuid↔回执） |
| br_customer | 委托方档案 |

### 8.3 数据流约束
- 业务单据"申报"成功 = 事务内 INSERT 镜像表 + 写 br_declare_log；
- 镜像表**不做 UPDATE 业务字段**；变更走 executeType=2 新增行。

## 9. 非功能需求
- 单据与镜像表写入同事务，保证不丢报；镜像表失败则单据回滚为待申报。
- 回执轮询间隔可配（默认 1 分钟）；自动补偿查询：20/21 状态超 30 分钟自动触发主动查询，当天每单上限 10 次。
- 全操作留痕（sys_oper_log）；金额数量 decimal(19,6) 精度。
- 报表导出 Excel（复用若依导出）。

**指标要求**（承草稿 §11）：
| 类别 | 指标 | 要求 |
|---|---|---|
| 性能 | 页面加载 / 查询响应 / 单据保存 | ≤3s / ≤2s / ≤1s |
| 性能 | 并发用户数 | ≥100 |
| 可靠性 | 申报及时性（审核通过→写入镜像表） | ≤5 分钟 |
| 可靠性 | 状态一致性 | 系统状态与海关状态最终一致 |
| 可靠性 | 异常单据 | 持久化不丢失，支持重报 |
| 安全 | 传输/访问/审计 | HTTPS、登录鉴权+权限校验、全操作日志 |
| 可用性 | 系统可用性 / 数据保留 | ≥99.9% / 业务数据≥3 年，日志≥6 个月 |
| 兼容性 | 浏览器 | Chrome/Firefox/Edge/Safari 最新 2 版，1366×768+ |

## 10. 验收标准（节选）
1. 以样例集 01（动力电池，全六类）为脚本走通：备案→入库→发料→收料（含服务费 0.1×460000）→出库→对账全 0，镜像表数据与样例 JSON 字段级一致。
2. 七个样例场景数据可分别回放并通过对账公式校验。
3. 模拟退单（result_status=N）后改单重报（executeType=2）流程可用。
4. SN 单件场景（样例 05）本期仅按批次口径回放对账，SN 台账列入二期。

### 11. 决议记录（已确认，2026-11-26）
1. 若依版本：**RuoYi-Vue 前后端分离版**（Spring Boot + Vue3/Element Plus）。企业用户 10~100 人，前后端分离版部署运维成本可控且利于长期扩展。
2. 部署模式：**单企业部署**，enterpCd / 企业名称 / 主管关区以若依参数配置（sys_config）维护，不做多企业数据隔离。
3. 回执获取：**轮询镜像表 + 公服回调接口 + 企业主动查询接口** 三种全部实现（轮询兜底，回调实时，主动查询用于对账核对）。
4. SN 单件管理：**本期不做**，管理粒度统一为批次；数据结构预留扩展。
5. 海关通关字典（计量单位/币制/国别/监管方式/征免方式）：**后续提供数据**，系统先建字典表并支持 Excel 导入。
6. 镜像表与业务库**同库**：客户端采集指向本库，申报=业务事务内写镜像表，避免跨库同步。
7. "复运回境内区外 + 维修费照章征税"场景（busiType=05）：**本期实现**。

详细设计见 `docs/design/保税维修工作台详细设计-V1.md`。
